# qomicex-downloader 下载核心架构设计

## 概述

面向 Minecraft 启动器 / 桌面 / Android App 的高性能 Rust 下载核心库（`crate-type = ["lib"]`），调用方为 Tauri 等桌面框架。核心设计目标：**激进（高并行、动态调整）+ 稳定（重试、看门狗、断点续传、原子完成）**。

## 模块结构

| 模块 | 职责 |
|------|------|
| `src/lib.rs` | 公开 API 导出（`DownloadManager`、`DownloadOptions`、`DownloadTask`、事件类型） |
| `src/error.rs` | `DownloadError`：Http/HttpStatus/Io/TaskNotFound/Cancelled/Incomplete/Exhausted/Other |
| `src/task.rs` | 任务模型：`DownloadTask`（builder 风格）、`TaskState` 状态机、`DownloadEvent` 三级事件、`DownloadOptions` 全局配置 |
| `src/segment.rs` | 段模型：`Segment`（闭区间 + 已下载计数）、`build_segments`（段大小导向切片）、`split`（动态拆分）、`align_to_part`（续传对齐） |
| `src/engine.rs` | 核心执行引擎：探测、调度循环（JoinSet）、动态拆分、分片级重试、看门狗、进度节流、流式回退 |
| `src/manager.rs` | 任务管理器：队列、两级并发控制（信号量 + 段上限）、暂停/恢复/取消、全局进度聚合、事件广播 |

## 下载流程

```
add(task) → 队列 → 派发循环(信号量) → worker
  → engine.run
    → probe (HEAD + Range 探测 + 镜像轮换)
    → 支持 Range:
        .part 对齐（断点续传）→ 调度循环（JoinSet 并发段）
        → 动态拆分（剩余字节最多的段二分）
        → 段任务（Range 请求 + 看门狗 + 指数退避重试 + 镜像）
        → 段失败耗尽 → 降级整文件流式重下
        → 校验 total → fsync → 原子 rename
    → 不支持 Range → 流式下载（append + 重试）
```

## 两级并发

- **全局 Worker 级**：`DownloadManager::new(opts, max_concurrent)`，`Semaphore` + `Notify` 派发循环
- **任务内段级**：`max_segments`（默认 16），调度循环 JoinSet 并发上限

## 关键机制

### 动态拆分
周期性（`split_sample_interval`，默认 2s）检查：活跃段中**剩余字节最多**且剩余 > 64KB 的段被二分（abort 原段，已写字节保留，新段从拆分点继续，重叠写幂等）。上限 `max_segments`。

### 看门狗（段级）
- 1s 周期检查：无数据超过 `watchdog_idle_timeout`（默认 30s）→ 判卡死
- 平滑速度 EMA（α=0.2）持续低于 `×0.3` 连续 `watchdog_slow_samples` 次 → 判龟速
- 触发后走段重试路径（重建段），重试日志含"看门狗"

### 重试与降级
- 分片级：指数退避 `base × 2^n` + 随机抖动(0..250ms)，上限 `max_retries`（默认 5）
- 分片耗尽 → 镜像轮换重试 → 全部耗尽 → **降级整文件流式重下**
- 服务器对整文件 Range 返回 200 视为合法（单段场景），部分段返回 200 视为忽略 Range 错误

### 断点续传
- 单 `.part` 文件 + seek 按 offset 写；段边界对齐（`align_to_part`）
- 暂停/取消：`CancellationToken` 中断在写盘边界，暂停保留 `.part`，取消删除
- 服务器不支持 Range 或 `.part` 大小异常（> total）→ 删 `.part` 从头下载

### 原子完成
`fsync`（Windows 必须用读写句柄，只读句柄 sync 返回 ACCESS_DENIED）→ rename（目标存在先删，兼容 Windows）

### 进度事件（三级）
- `Progress`：任务级，节流 `progress_throttle`（默认 150ms）合并上报，含速度/活跃段数
- `GlobalProgress`：manager 聚合，周期 `global_progress_interval`（默认 250ms）
- `Log`：重试/拆分/看门狗/降级等诊断信息
- 通道：`tokio::sync::broadcast`（容量 1024）

## 平台兼容

纯 Rust 依赖栈（rustls TLS，无 OpenSSL/native-tls）。支持 Windows / macOS / Linux / Android。注意点：
- Windows：只读句柄 `sync_all` 报 ACCESS_DENIED（见原子完成）；rename 目标存在需先删
- Android：需要 NDK 交叉编译（见系统要求文档），ring 编译需要 `aarch64-linux-android-clang`

## 已知边界与二期预留

- **镜像选择（IP 粒度测速直连）**：本期仅镜像 URL 轮换（重试/探测失败时），完整 DNS 解析 + EMA 测速 + IP 直连需自定义 hyper connector，二期
- **SHA-256 校验**：未实现（API 预留空间）
- 小文件（≤ `split_threshold`，默认 10MB）单请求直传，不做分段

### 2026-08-07 更新
### 完整性校验（SHA-256，可选）
- `DownloadTask::with_sha256` / `with_sha256_hex` 指定校验和（分块流式计算，内存友好）
- 校验时机：finalize（rename）前对 `.part` 计算并比对
- 校验失败：删除 `.part` 自动重下一次；仍失败 → `ChecksumMismatch`（Failed），不残留目标文件与 `.part`
- 流式路径（无 Range）完成时同样校验；且 total 已知时 EOF 校验字节数一致（chunked 截断兜底）

### 失败重试（任务级）
- `manager.retry(id)`：Failed / Cancelled 任务重新入队；`.part` 存在则续传，否则从头下载
- 状态机补充：`Failed / Cancelled → Queued`

### 流式重试防叠加
- 流式路径每次尝试前删除 `.part`（流式无断点续传），防止重试时 append 叠加造成文件膨胀
